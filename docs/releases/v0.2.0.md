# ExpressionForge v0.2.0 — Expression correctness

ExpressionForge 0.2.0 turns the initial proof of concept into a more dependable foundation for building and executing portable query expressions.

## Highlights

- **Stable expression node IDs:** Optional, unique node identifiers survive JSON round-trips and make editor diagnostics precise without changing SQL semantics.
- **Typed runtime parameters:** Save reusable JSON query definitions and supply values separately for validation, compilation, and SQL Server preview.
- **Visual parameter inspector:** The browser editor discovers named inputs across nested groups and collection scopes, checks their types, and builds bound requests.
- **Correct SQL collection semantics:** SQL Server 2022 integration tests verify `ANY`, `ALL`, `NONE`, empty collections, `NULL` / SQL UNKNOWN, and negation.
- **Validation hardening:** Conflicting parameter types, ignored null-check values, and misattributed child diagnostics are rejected or corrected.
- **Complex, executable examples:** Five nested scenarios on the GitHub Pages website are compiled by .NET tests and executed against SQL Server in CI.
- **Release automation:** Version changes merged into `main` now trigger the verified GitHub Release pipeline.

## Try it

Project website: https://matrtech.github.io/ExpressionForge/

Advanced examples: https://matrtech.github.io/ExpressionForge/#examples

Run the actual editor and API with the .NET 10 SDK:

```bash
dotnet restore ExpressionForge.slnx
dotnet run --project src/ExpressionForge.Api --urls http://localhost:5054
```

Open http://localhost:5054. SQL Server is optional for validation and compilation, but required for database row preview.

## Compatibility

- Existing JSON AST version 1 definitions remain supported; node IDs are optional.
- The package is still a **pre-1.0 preview**, not a stable production API.
- Queries are read-only and SQL Server-specific; use a restricted read-only SQL login.
- This release publishes a GitHub Release with the NuGet package artifact and API archive. **It does not publish to NuGet.org.**
